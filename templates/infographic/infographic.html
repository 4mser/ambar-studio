AMBAR Studio · how it works

One page in, every format out.

A piece starts as a web page. Chrome draws it, AMBAR records what it draws, and the same page leaves as a video, a deck, a document or a set of images.

01

Write a page

HTML and CSS for the picture, JavaScript for the motion. A video exposes render(t), and the picture depends on t alone.

02

Chrome draws it, frame by frame

Headless Chrome opens the page and asks for one moment at a time. Any frame can be drawn again, in any order, with the same result.

03

The same page, four formats

How the page leaves the browser is the only difference between a video, a deck, a document and a set of images.

04

Checked before it ships

Every export is checked by machine first. A person still looks at the result, with the contact sheet in front of them.

Nothing leaves the frame

Text and images that cross the edge are errors, not warnings.

Every box holds its content

overflow: hidden clips silently, so a clipped box is reported.

Static fonts only

A variable or faked font prints as Type 3 glyphs: the PDF scan finds them.

No shadows on paper

Shadows stay on screen; Preview prints them as grey blocks.
